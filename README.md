# جديد — نموذج تفاعلي (React + Tailwind CSS)

نموذج MVP تفاعلي كامل لتطبيق «جديد» (متسوّق + تاجر) مبني على تصميم Figma
`Jadeed UI`، مع تصحيح أخطاء التصميم وتطبيق منطق حقيقي للسلة والطلبات.

## التشغيل

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # الإخراج في dist/
npm run preview    # معاينة نسخة الإنتاج
```

## نقطة الدخول (Landing للمطوّر / المُقيّم)

عند فتح التطبيق تظهر شاشة ترحيبية بخيارين:

| الخيار | الرابط | الوصف |
|---|---|---|
| **معرض الشاشات** | `#/gallery` أو `#/gallery/<key>` | 87 شاشة وحالة مصنّفة في 9 فئات (التهيئة، التسجيل، الموقع، العميل، السلة والطلبات، الحساب، توثيق التاجر، لوحة التاجر، المكونات المستقلة). كل شاشة تُعرض معزولة بحالتها الخاصة (`src/gallery/catalog.js`) مع بحث بالاسم/الرمز، تنقّل بالأسهم ← →، وزر إعادة ضبط. |
| **تجربة النموذج الأولي** | `#/prototype` | التطبيق التفاعلي الكامل من شاشة البداية (Splash → التهيئة → نوع الحساب → الدخول/OTP → التسوق → السلة → الطلب → التتبع) مع لوحة عرض جانبية واختصارات. |

## بيانات العرض التجريبي

| العنصر | القيمة |
|---|---|
| تسجيل الدخول | أي بريد صالح أو رقم يبدأ بـ `7` من 9 أرقام (مثال `773030064`) |
| رمز التحقق OTP | `1234` (4 أرقام — 3 محاولات خاطئة ⇒ قفل مؤقت CUS-006) |
| كوبونات الخصم | `JADEED20` (20%) · `WELCOME10` (10%) · `FLAT2000` (خصم ثابت) |
| محاكاة فشل التسجيل | بريد يحتوي على كلمة `fail` |
| أرقام الطلبات | صيغة موحّدة `JD-XXXXXX` (أول طلب جديد `JD-984210`) |

على الشاشات العريضة تظهر **لوحة العرض (Demo Panel)** يسار الهاتف وفيها اختصارات
(إعادة التشغيل، الدخول كعميل، لوحة التاجر، شاشة الدخول، رحلة توثيق تاجر) وقراءة حيّة للحالة.

## ما تم تصحيحه مقارنةً بالتصميم

- **Design Tokens موحّدة** في `tailwind.config.js`: `primary #5002C9`، `secondary #FF5715`،
  تدرّج رمادي واحد `ink 50–900`، ألوان الحالات، نصف الأقطار، الظلال.
- **OTP = 4 أرقام** في كل الشاشات (الرسالة، الحقول، القفل).
- **أرقام الطلبات** بصيغة واحدة `JD-XXXXXX` في السلة/التتبع/الفاتورة/لوحة التاجر.
- **شريط تنقّل سفلي موحّد** (ترتيب وأيقونات ثابتة، RTL) للعميل وللتاجر.
- **حسابات السلة رياضية حقيقية**: المجموع الفرعي − الخصم + التوصيل = الإجمالي (لا أرقام ثابتة).
- تصحيح الأخطاء الإملائية والمنطقية في النصوص.

## المنطق التفاعلي (Context API + useReducer)

- إضافة للسلة تزيد العدّاد فعلياً، تعديل الكميات، حذف، كوبونات، إتمام الطلب.
- دورة حياة الطلب: جديد → مقبول → قيد التحضير → جاهز → خرج للتوصيل → تم التوصيل
  (تتقدّم تلقائياً أو يدوياً من لوحة التاجر، وتنعكس فوراً على تتبع العميل).
- مصادقة كاملة: اختيار نوع الحساب، دخول/تسجيل مع تحقق من المدخلات، OTP، قفل المحاولات.
- الموقع والعناوين: إذن الموقع، نجاح/رفض، عناوين محفوظة، إضافة عنوان.
- التاجر: رحلة التوثيق (M-042 → M-049/M-048)، لوحة التحكم، الطلبات الواردة وتحديث المراحل،
  المنتجات (إضافة/تعديل/حذف مع تأكيد)، الإحصائيات.

## الشعار الرسمي

- الشعار المعتمد هو الملف المرسل من العميل (الاسم العربي «جديد» + JADEED + العلامة البرتقالية/البنفسجية، بخلفية شفافة). الملف الأصلي محفوظ كما هو في `public/assets/logo-source.png`، والنسخة المستخدمة `public/assets/logo.png` مطابقة له بكسلاً ببكسل بعد إزالة الهوامش الشفافة الفارغة فقط (لا قصّ لأي جزء مرئي، ولا إعادة تلوين).
- الشعار السابق (المربع الأسود 120×120) ومشتقّاته حُذفت نهائياً من المشروع.
- المكوّن `Logo` في `src/components/ui.jsx` يعرضه عبر `<img>` بـ:
  - **ارتفاع ثابت** (`size` بالبكسل، أو صنف Tailwind مثل `className="h-12"`) و**عرض تلقائي** `w-auto`؛
  - `object-fit: contain` و`max-w-none` ⇒ لا تمطيط ولا قصّ مهما كانت الحاوية؛ نسبة العرض إلى الارتفاع = نسبة الصورة الأصلية دائماً (3.61:1).
  - `<Logo size={n} />` → الشعار الكامل (Splash داخل لوحة بيضاء، الدخول، التسجيل، الهيدر الموحّد، هيدر معرض الشاشات، صفحة الهبوط، دخول الإدارة).
  - `<Logo light />` → على الخلفيات البنفسجية/الداكنة (لوحة بيضاء خلف الشعار ليبقى الاسم الكحلي مقروءاً).
  - `<Logo icon />` → العلامة وحدها (مربعة) للمواضع الضيقة جداً (معاينة شعار المتجر، الأيقونات).

## ضمان الجودة (QA) — وضع النموذج التفاعلي

نُفِّذ تدقيق آلي كامل بـ Playwright على وضع النموذج (`#/prototype`) قبل الإصدار (Release Candidate) — **71/71 فحص ناجح**:

| المحور | ما تم التحقق منه |
|---|---|
| المصادقة | رفض البريد غير الصالح، قبول رقم `7xxxxxxxx`، OTP من 4 خانات، عدّاد المحاولات، القفل المؤقت |
| منطق السلة | سلة مركّبة (5 منتجات، تغيير كميات، كوبون صالح/غير صالح، حذف منتج، تبديل كوبون) — كل مجموع يُطابق الحساب اليدوي لحظيًا وينعكس على الدفع والفاتورة |
| دورة حياة الطلب | فشل الشبكة → شاشة الفشل الكاملة → إعادة المحاولة → نجاح → تتبّع → فاتورة؛ رفض/قبول التاجر، تجهيز، جاهز، خرج للتوصيل، تم التسليم |
| الشاشات المُستعادة ★ | «تم رفض الطلب»، «تم قبول الطلب»، «تم تعديل المنتج»، «تم حذف المنتج»، «تم اعتماد المتجر» تظهر كشاشات كاملة داخل التدفّق نفسه |
| RTL والنظافة البصرية | أرقام الطلبات `JD-XXXXXX` داخل `dir="ltr"` (لا انقلاب)، لا تداخل/تجاوز نصوص في 12 شاشة، شريط التنقّل سليم، ملاءمة 360×640 بلا تمرير أفقي، خط Cairo |
| الكونسول | لا أخطاء وقت تشغيل، لا تحذيرات React key، لا طلبات فاشلة |

كما يُفحص معرض الشاشات (91 عنصرًا) آليًا: لا شاشة فارغة ولا أخطاء كونسول.

- **أكواد Figma المرجعية (CUS-0xx / M-0xx) أُزيلت من واجهة الهاتف** (الهيدر، أزرار الإجراءات، النصوص المساعدة، رسائل Toast). تبقى الأكواد فقط في بطاقات معرض الشاشات وقائمته الجانبية خارج الإطار — لأغراض المطابقة مع التصميم — وفي `SCREENS-COVERAGE.md`.

## ملاحظات إصدار (RC-4)

- **شاشة «تفاصيل المتجر وقائمة المنتجات» (Figma 11:1464)** أُعيد بناؤها لتطابق التصميم: غلاف المتجر مع زر الرجوع، بطاقة المتجر المتداخلة (الشعار/العلامة، الاسم مع شارة التوثيق، الحي والمدينة، شارتا «معتمد ومفتوح» و«متجر رسمي موثوق»)، عنوان «قائمة منتجات المتجر» مع العدّاد، شبكة بطاقات المنتجات (صورة كبيرة + الاسم بسطرين + السعر + زر **+** يضيف فعلياً إلى السلة مع شارة الكمية)، وزر «العودة إلى الرئيسية» ثابت أسفل الشاشة. الوصول إليها من بطاقات المتاجر في الرئيسية، وقائمة «المتاجر القريبة»، ورابط المتجر في صفحة المنتج.
- **«المتجر فارغ حالياً» (CUS-020 · 11:1426)** صارت شاشة مستقلة بهيدر خاص وزر «تصفح متاجر أخرى» كما في التصميم (تظهر تلقائياً لأي متجر بلا منتجات — مثلاً بعد حذف التاجر لكل منتجاته).
- إصلاح: ملف `logo-icon.png` (العلامة المربعة للأيقونات) كان شفافاً بالكامل بسبب خطأ في القصّ؛ أُعيد توليده من الشعار الرسمي ويُستخدم الآن في بطاقة المتجر ومعاينة رفع الشعار وأيقونة المتصفح.
